## 스크롤 연출

- **스티키 핀 씬.** 히어로 sticky 부모 높이 2700px(3 뷰포트), 첫 씬 묶음 8550px(9.5 뷰포트). 다음 sticky 그룹은 1710px, 4928px에서 시작.
- **스케일.** 영상 래퍼가 `scale(1.2)` → 스크롤 900px에 1.0125 → 1800px에 1.0. 바깥 컨테이너도 0.752 → 0.833으로 커지며 카드 인셋에서 풀블리드가 된다. transform만 쓴다.
- **장면 전환.** 풀블리드 사진이 둥근 카드(약 62% 폭)로 줄어든다. 그 안에서 폰이 카드 밖으로 튀어나오며 커지고, 그 폰이 다음 섹션의 고정 앵커가 된다(왼쪽 기능 목록이 바뀌는 동안 폰은 오른쪽에 고정).
- **텍스트 단계 등장.** "몇 번만 누르면" 뒤에 "끝나는 송금"이 줄 단위로 추가된다. 40px / 700 / 56px / -0.8px(-0.02em), 흰색, 영상 위.
- **다음 섹션 타이포.** 48px / 700 / 61.44px(1.28) / -0.96px(-0.02em) / #1c1f25. 본문 16px / 400 / 25.6px(1.6) / #727780.
- **배경.** 흰 바탕 + 사진·영상 풀블리드. 강조는 블루(#3182f6 계열) 소량. 다크 풀블리드 장면은 사진 자체로 만든다.
- **모바일.** 핀을 줄이고 세로로 쌓는다. 섹션 헤드 36px / 700 / 1.28, 카드 제목 18px, 본문 14px / 1.6. 폰 목업은 화면 폭의 80~90%로 크게 쓴다.
- **CTA.** 첫 화면에 CTA가 없다. 내비의 '앱 다운로드'와 섹션별 작은 pill(고스트 + 화살표 원)이 전부다. 메시지와 비주얼이 먼저다.

## PLUCK 적용 원칙(그대로 베끼지 않기)

1. 첫 화면은 거대한 헤드라인과 최소 요소만 둔다. PLUCK은 상담이 목적이라 CTA 2개는 유지한다.
2. 사진·영상 대신 실제 프로젝트 화면을 주인공으로 쓴다. 브라우저 프레임이 첫 화면 하단에서 엿보이다가 풀블리드로 커지고(toss의 1.2→1.0 역방향), 카드로 줄며 옆으로 비켜난다.
3. 핀 씬 안에서 큰 문장이 단계별로 교체된다(기획부터 → 디자인 → 개발 → AI 자동화까지). 문장마다 해당 실제 사례 화면으로 교체된다.
4. 앱 화면은 폰 단위로 크롭해 카드 주변으로 날아오게 한다.
5. transform/opacity만 쓰고, reduced-motion에서는 정적 레이아웃으로 둔다.
